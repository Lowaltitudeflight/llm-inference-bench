## 表单填写

### 文章标题

从这三选一（正文文件里已有第一个）：

```
我把 8 卡 72B 的压测经验写成了开源工具：聊聊 LLM 推理压测里最容易写错的 5 件事
```

备选（更短，适合移动端展示）：

```
LLM 推理压测最容易写错的 5 件事（附开源工具）
```

```
从 TTFT 到多卡显存峰值：我踩过的 5 个 LLM 压测坑
```

> 掘金标题上限约 60 字，第一个是 41 字，安全。

### 分类

**后端**（推荐）

理由：内容偏工程实现与性能测量，不是纯算法/模型研究。掘金「人工智能」分类下多是模型、微调、论文解读，压测工程放「后端」更容易被目标读者看到。

### 标签

掘金最多 **5 个**，按顺序填（第一个权重最高）：

```
vLLM
LLM
性能优化
Python
开源
```

### 封面

可选。**建议不用自动生成的封面**——掘金会给个灰底文字图，比较难看。
如果要自己配，用仓库里跑出的报告截图（`data/results/demo/report.html` 打开后截图）最贴题。

### 摘要 / 描述

```
部署完大模型之后，怎么证明它跑得好？本文分享 LLM 推理压测中 5 个容易写错的指标口径：TTFT 必须流式测、TPOT 分母要减 1、吞吐不能算输入 token、多卡显存峰值不能取各卡最大值、分位数要用线性插值。附开源压测工具与真实数据。
```

## 发布步骤

1. 打开 https://juejin.cn/editor/drafts/new
2. 右上角切到 **Markdown 模式**（掘金默认是富文本，一定要切）
3. 打开 `docs/article-llm-bench-5-pitfalls.md`，**全选复制**正文
4. 粘贴进编辑器
5. 填上面给的标题 / 分类 / 标签 / 摘要
6. **发布前检查这三处：**
   - 文中 Gitee 链接能否点开
   - 表格是否正常渲染（掘金表格偶尔会吃掉表头）
   - 代码块有没有高亮（没高亮就手动选一下语言）

## 发完之后的动作

**1. 把链接加到简历**

Gitee 那一行旁边加一句即可，比只放仓库地址有效：

```
技术文章：https://juejin.cn/post/xxxxx
```

**2. 同步到知乎**

掘金发完可直接复制到知乎（知乎支持 Markdown 粘贴）。知乎的长尾搜索流量比掘金好，技术问题容易长期被搜到。

**3. 如果数据还行，可以再写一篇**

第二篇的选题建议（都基于项目里真实做过的事）：

- `多卡 GPU 显存监控踩坑：为什么不能取各卡最大值`
- `写给后端看的 LLM 指标入门：TTFT / TPOT / P99 到底在测什么`
- `私有化交付的 HTML 报告：为什么必须做成自包含`

这三篇都比第一篇更聚焦，适合拆成系列。
